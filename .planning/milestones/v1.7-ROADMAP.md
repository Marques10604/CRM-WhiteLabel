# Milestone v1.7: Exploração de Nicho

**Status:** ✅ SHIPPED 2026-09-12
**Phases:** 22-25
**Total Plans:** 16

## Overview

Dar ao CRM o objeto de 1ª classe que é o diferencial real do produto — a campanha de exploração
de nicho, com diagnóstico de IA anti-genérico, veredito registrado pelo usuário e o loop de
resultado real fechando com o que `/relatorios` já calcula. Zero WhatsApp, zero VPS, zero infra
nova. Direção completa em `.planning/DIRECAO-v1.7-2026-09-04.md` (Caminho A escolhido: construir
o objeto "nicho/campanha" dentro do CRM atual, sem fundir com o Prospector).

### Phase 23: Diagnóstico de IA da Campanha

**Goal**: O usuário gera, sob demanda, um diagnóstico de IA anti-genérico para a campanha — com busca na web, fontes citadas, distinção clara entre dado quantificável e alegação de marketing, e um veredito sugerido que nunca é vinculante.
**Depends on**: Phase 22
**Requirements**: DIAGNOSTICO-01..10
**Plans**: 7 planos em 5 ondas

- [x] 23-01-PLAN.md — Contrato Zod do diagnóstico, fixtures de referência e harness estrutural anti-genérico
- [x] 23-02-PLAN.md — [BLOCKING] Tabela `diagnosticos`: schema Drizzle, migração `.cjs` idempotente e gate de schema
- [x] 23-03-PLAN.md — Núcleo de IA: portão de pacote, instalação do AI SDK, system prompt e `gerarDiagnostico()`
- [x] 23-04-PLAN.md — Server Action de geração, setup do usuário (chave + Web Search) e spike de config do Sonnet 5
- [x] 23-05-PLAN.md — Componentes de apresentação: badges dado×marketing, veredito, rascunho e resultado
- [x] 23-06-PLAN.md — Eval on-demand: dataset de nichos de referência, LLM-judge e baseline dos 3 gold
- [x] 23-07-PLAN.md — Seção de diagnóstico em `/campanhas/[id]`: botão, estados vazio/erro/resultado e histórico

**Detalhes:** completado 2026-09-11. Primeira feature de IA do projeto (`workflow.ai_integration_phase: true`). Eval on-demand: rodadas 1-2 não discriminaram os 3 nichos-gold (dicotomia falsa no schema de achado); D-23-06 corrigiu com 3ª categoria (`relato_qualitativo`); rodada 3 discriminou os 3 vereditos gold pela 1ª vez. Code review achou 2 críticos, corrigidos. Dívida técnica aceita: variância de veredito entre execuções idênticas (comportamento esperado, não bug); sufixo espúrio em URLs do cross-check de citações (bug real, não-bloqueante). `23-VERIFICATION.md` ficou `human_needed` — UAT visual da geração real pendente por falta de crédito de API na sessão.

## Milestone Summary

**Key Decisions:**

- Framework de IA: Vercel AI SDK (`generateText` + `Output.object` + tool `web_search`), não `generateObject` (não aceita tools)
- Schema de achado do diagnóstico evoluiu de 2 para 3 categorias (D-23-06) — causa raiz da não-discriminação do eval era uma dicotomia falsa no schema, não uma rubrica frouxa
- Variância de veredito da IA entre execuções idênticas: aceita como comportamento ESPERADO — o veredito da IA é sempre sugestão de 1 execução, o operador sempre valida
- `registrarVeredito` só transiciona `campanhas.estado` pra `veredito_registrado` — `em_escala`/`abandonada` ficam declaradas no enum mas inalcançáveis nesta fase (fora do escopo dos requisitos)
- Persistência do tour via `localStorage`, não a tabela `configuracoes` — mesmo padrão do dark mode (Fase 20), evita acoplamento de schema pra preferência de UI
- Execução sequencial sem worktree mantida em todo o milestone (host 4GB) — zero OOM/crash, custo é onda mais lenta
- `gsd-plan-checker` com revisão obrigatória (Fases 24 e 25) achou bugs reais antes do código existir — validou o valor do gate

**Issues Resolved:**

- CAMPANHA-03 (gap silencioso, Fase 22) fechado pelo plano 22-03
- Não-discriminação do eval de diagnóstico (Fase 23) resolvida com a 3ª categoria de achado
- 2 críticos + avisos de code review corrigidos em cada uma das 3 últimas fases (23, 24, 25)

**Issues Deferred:**

- UAT visual no navegador das Fases 23/24/25 — host sem browser disponível nas sessões de verificação (mesmo padrão desde a Fase 18)
- Geração real de diagnóstico não vista rodando por um humano — falta de crédito de API
- Sufixo espúrio em URLs do cross-check de citações (Fase 23) — bug real, não-bloqueante, investigação futura
- 26 itens de débito pré-existente (14 quick-tasks, 5 todos, 2 seeds, 2 verification gaps já contados acima) reconhecidos em `STATE.md` no fechamento — maioria de julho/agosto, anterior ao v1.7

**Technical Debt Incurred:**

- IN-01 do code review da Fase 25 (`tourId`/`data-tour` duplicados sem checagem de sincronismo) — info-level, não corrigido
- WR-02/WR-03 do code review da Fase 23 (gate duplicado morto, log de `err.cause` sem checar forma) — não corrigidos
