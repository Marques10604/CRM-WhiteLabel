<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| querystring `?period=` → `resolvePeriodRange` | valor totalmente controlado pelo cliente, chega como string arbitrária vinda da URL |
| `PeriodRange` → cláusula SQL `where` | as datas resolvidas viram parâmetros de comparação nas três agregações |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-19 | Denial of Service | valor de `period` inválido/adulterado derrubando a rota com exceção não tratada | mitigate | `resolvePeriodRange` aceita `string \| undefined` e cai silenciosamente em `{ start: new Date(0), end: now }` para QUALQUER valor fora do enum; a função não contém `throw`, coberto por asserção dedicada no `test:relatorios` |
| T-11-20 | Tampering | injeção SQL via `period` chegando à cláusula `where` | mitigate | O valor nunca é interpolado em SQL — é convertido em objetos `Date` pela função pura antes de virar parâmetro do Drizzle; caso de teste com payload `'; DROP TABLE leads; --` prova que o valor é descartado |
| T-11-21 | Information Disclosure | agregações expondo leads soft-deletados (que estão na Lixeira) | mitigate | `isNull(leads.deletedAt)` obrigatório nas três queries, com caso de teste dedicado |
| T-11-22 | Tampering | `count(*)`/`sum(case when ...)` errados produzindo relatório enganoso (integridade de dado, não de segurança) | mitigate | Cobertura de integração das 3 agregações em banco isolado, mais o teste de mutação de D-11 exigido nos critérios de aceitação |
| T-11-23 | Elevation of Privilege | leitura de métricas sem autenticação | accept | Ferramenta solo-admin local sem auth (PROJECT.md/CLAUDE.md); ASVS V2/V3/V4 não se aplicam |
</threat_model>
