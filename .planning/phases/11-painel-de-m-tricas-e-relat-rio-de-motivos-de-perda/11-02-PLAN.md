<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| navegador → Server Action | `nome` de motivo é texto livre digitado pelo admin, cruza para o servidor via FormData |
| Server Action → SQLite | escrita em `motivos_perda`; nome do motivo é usado em comparação SQL case-insensitive |
| dado do banco → JSX | nome do motivo é renderizado na lista de `/motivos-perda` e nos toasts |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-06 | Tampering | injeção SQL via `nome` livre em `createMotivoPerda`/`renameMotivoPerda` | mitigate | ASVS V5 — `motivoPerdaSchema.safeParse` no topo de cada action + comparação via template `sql` do Drizzle (placeholders parametrizados do better-sqlite3); zero concatenação de string crua |
| T-11-07 | Tampering | mass-assignment via FormData extra em `createMotivoPerda` | mitigate | O `safeParse` lê APENAS `formData.get("nome")`, nunca `Object.fromEntries(formData)` — campos extras enviados pelo cliente são ignorados por construção |
| T-11-08 | Tampering | id forjado/não-inteiro em `softDeleteMotivoPerda` / `renameMotivoPerda` | mitigate | Guarda `Number.isInteger(id) && id > 0` antes de qualquer escrita; UPDATE escopado por `eq(id)` — jamais um UPDATE sem WHERE |
| T-11-09 | Tampering | XSS via nome de motivo renderizado na lista/toast | mitigate | React escapa por padrão; proibido `dangerouslySetInnerHTML` nos dois componentes novos — verificado no code review |
| T-11-10 | Denial of Service | remoção de motivo em uso derrubando leads perdidos | mitigate | Soft-delete apenas (`deletedAt`), FK `onDelete: "restrict"` e guard `npm run guard:no-hard-delete` estendido a `motivos_perda` no plano 11-01 |
| T-11-11 | Elevation of Privilege | acesso não autenticado a `/motivos-perda` | accept | Ferramenta solo-admin local sem auth por decisão explícita de PROJECT.md/CLAUDE.md; ASVS V2/V3/V4 marcados como "não aplica" em 11-RESEARCH.md §Security Domain |
</threat_model>
