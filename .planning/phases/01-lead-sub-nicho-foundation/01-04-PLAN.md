## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-11 | Repudiation / Perda de dados | Exclusão de lead | mitigate | Soft-delete obrigatório (LEAD-04): `db.update` de `deletedAt`, NUNCA `db.delete(leads)`; dado permanece recuperável via Lixeira — este é o próprio requisito, não só boa prática (substitui a planilha, sem backup externo). Reforçado por guarda repetível e portável (`scripts/guard-no-hard-delete.cjs`, script Node sem dependência de shell) que varre `src/` + `scripts/` + `src/db/migrations/`, pegando hard-deletes ou SQL destrutivo introduzidos em qualquer script/utilitário/componente/migração futura, de forma consistente entre Git Bash/PowerShell/npm.cmd |
| T-01-12 | Tampering | softDeleteLead/restoreLead (leadId) | mitigate | `leadId` usado apenas em `where(eq(leads.id, leadId))` via query parametrizada do Drizzle; nenhum outro campo é escrito a partir de input do cliente (apenas `deletedAt` é setado pela própria action) |
| T-01-13 | Tampering | Soft-delete bypass (query da lista ativa) | mitigate | A lista ativa filtra por `isNull(deletedAt)` e a Lixeira por `isNotNull(deletedAt)`; um lead nunca aparece nas duas — a query é a fonte de verdade da visibilidade. Actions de delete/restore são idempotentes (restritas por `isNull`/`isNotNull` no `where`), evitando reescrever estado já correto |
| T-01-SC | Tampering | Dependências npm | accept | Nenhuma instalação nova neste plano (o guard usa só módulos nativos do Node) |
