<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser (Client Component) -> Server Action | Input do formulário de sub-nicho cruza para o servidor; deve ser revalidado com Zod no server, nunca só no client |
| Server Action -> SQLite (Drizzle) | Toda escrita passa por query parametrizada do Drizzle; nenhum `sql.raw()` com input de usuário |
| npm registry -> ambiente de build | Instalação de dependências (supply chain) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Tampering | createSubnicho / renameSubnicho (input do formulário) | mitigate | Validar com `subnichoSchema` (`safeParse`) no server antes de tocar o Drizzle; `parsed.data` só contém `nome`, ignorando campos extras do FormData (inclui `$ACTION_*`) — barra mass-assignment |
| T-01-02 | Tampering | Índice único de sub-nicho (race de duplo-clique) | mitigate | `uniqueIndex("subnicho_nome_unique_idx")` sobre lower(trim(nome)) no schema + try/catch da violação de constraint na Server Action (Pitfall 1) |
