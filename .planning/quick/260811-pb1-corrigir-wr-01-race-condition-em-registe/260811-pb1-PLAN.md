# Quick Task 260811-pb1: Corrigir WR-01 — race condition em registerWhatsAppContact

## Problema

`src/actions/lead-actions.ts:239-263` (`registerWhatsAppContact`) calcula `advanced` a partir de um `SELECT` (`current.stage === "novo"`) que roda **antes** de `db.transaction()` abrir. O `UPDATE` transacional que segue não reverifica `stage` no `WHERE` — só filtra por `id` e `isNull(deletedAt)`.

Se um `updateLeadStage` concorrente (drag-and-drop para "negociacao"/"fechado"/"perdido") commitar entre o `SELECT` pré-transação e o `UPDATE`, `advanced` continua `true` a partir da leitura obsoleta, e a transação sobrescreve incondicionalmente `stage: "contatado"` — exatamente o cenário que o docstring da função afirma nunca acontecer. Clássico check-then-act (TOCTOU), realista mesmo em uso solo (o clique de WhatsApp é fire-and-forget enquanto a aba abre; um drag rápido do mesmo card logo em seguida cai nessa janela).

## Fix

Re-verificar `stage` dentro do próprio `WHERE` da escrita atômica, usando `.returning()` para detectar se a guarda barrou a escrita (0 linhas casadas quando `advanced` era esperado):

### Task 1: Reverificar stage no WHERE da transação + `.returning()`

**Files:** `src/actions/lead-actions.ts`

**Action:**
1. Adicionar `stageGuard = advanced ? [eq(leads.stage, "novo")] : []` antes da transação
2. Adicionar o spread `...stageGuard` no `.where()` do update transacional
3. Adicionar `.returning({ id: leads.id })` ao update
4. Se `advanced` era `true` mas o `.returning()` voltou vazio (0 linhas) → o stage mudou concorrentemente; recalcular `advanced = false` para o retorno da função (a interação/contagem já foi gravada, só o auto-avanço de etapa é abortado)
5. Atualizar o comentário JSDoc da função (linhas ~211-215) removendo a afirmação de que a corrida "nunca sobrescreve" — descrever a guarda real (reverificação atômica no WHERE)

**Verify:**
```bash
npx tsc --noEmit
npm run test:interacao-actions
node scripts/verify-wa-contact-invariant.cjs
npm run guard:no-hard-delete
```

**Done:** `registerWhatsAppContact` não sobrescreve mais um `stage` manual concorrente; todos os gates acima em exit 0; `advanced` retornado ao caller reflete a realidade pós-escrita, não a leitura pré-transação.

## Scope

Único arquivo tocado: `src/actions/lead-actions.ts`. Nenhuma mudança de schema, nenhuma mudança de UI — o toast de auto-avanço no client já lida com `advanced: false` (não exibe o toast), então nenhuma superfície de UI precisa mudar.
