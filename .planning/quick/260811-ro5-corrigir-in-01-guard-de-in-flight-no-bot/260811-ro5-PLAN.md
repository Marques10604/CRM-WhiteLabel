# Quick Task 260811-ro5: Corrigir IN-01 — guard de in-flight no botão de excluir nota manual

## Problema

`src/components/lead-timeline-dialog.tsx:140-151` (`handleConfirmarExclusao`) `await`s `softDeleteInteracaoManual(id)` sem nenhuma flag de pending, diferente dos fluxos irmãos no mesmo arquivo: `onSubmit` (criar) usa `pending` de `useTransition`, `handleSalvarEdicao` (editar) usa `salvandoEdicaoId`. O botão "Excluir" de `DeleteNotaDialog` (`delete-nota-dialog.tsx:40`) nunca é desabilitado durante a requisição — um duplo-clique rápido dispara `softDeleteInteracaoManual` duas vezes em concorrência. Inofensivo hoje só porque a ação já é idempotente (`WHERE ... AND deleted_at IS NULL`), mas é uma inconsistência com o resto do próprio arquivo.

## Fix

Espelhar o padrão já usado por `handleSalvarEdicao`/`salvandoEdicaoId`: uma flag local de pending para a exclusão, desabilitando o botão "Excluir" de `DeleteNotaDialog` enquanto a requisição está em voo.

### Task 1: Flag de pending na exclusão + prop `pending` em DeleteNotaDialog

**Files:** `src/components/lead-timeline-dialog.tsx`, `src/components/delete-nota-dialog.tsx`

**Action:**
1. Em `lead-timeline-dialog.tsx`: adicionar `const [excluindo, setExcluindo] = useState(false)`
2. `handleConfirmarExclusao`: `setExcluindo(true)` no início, `try/finally` com `setExcluindo(false)` no finally (mesmo padrão de `handleSalvarEdicao`)
3. Resetar `excluindo` para `false` no mesmo `useEffect [open, lead?.id]` que já reseta `editandoId`/`notaParaExcluir` (mantém uma única fonte de reset ao trocar de lead, mesmo padrão já estabelecido em 09-03)
4. Passar `pending={excluindo}` para `<DeleteNotaDialog>`
5. Em `delete-nota-dialog.tsx`: adicionar prop opcional `pending?: boolean` ao `DeleteNotaDialogProps`; desabilitar o botão "Excluir" (`disabled={pending}`) e trocar o texto para "Excluindo..." quando `pending` for `true` (mesmo padrão textual de `onSubmit`/"Salvando...")

**Verify:**
```bash
npx tsc --noEmit
npx eslint src/components/lead-timeline-dialog.tsx src/components/delete-nota-dialog.tsx
npm run test:interacao-actions
```

**Done:** Botão "Excluir" de `DeleteNotaDialog` fica desabilitado (texto "Excluindo...") enquanto `softDeleteInteracaoManual` está em voo, prevenindo duplo-clique concorrente; os 3 gates acima em exit 0.

## Scope

2 arquivos tocados: `lead-timeline-dialog.tsx`, `delete-nota-dialog.tsx`. Não toca `delete-lead-dialog.tsx` (mesmo padrão ausente lá, mas fora do escopo do IN-01, que é específico da timeline) nem nenhuma Server Action — a idempotência do servidor já é garantida e continua sendo a defesa real, esta é só a UI parar de permitir a segunda requisição desnecessária.
